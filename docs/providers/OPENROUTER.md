# OPENROUTER — Capacidades e limitações reais (documentação consultada em 24/11/2026)

Fonte: documentação oficial em https://openrouter.ai/docs (páginas: quickstart, api_reference/overview, models, structured-outputs, provider-selection, reasoning-tokens, server-tools/web-search, plugins/web-search, multimodal/pdfs, batch-api, prompt-caching, usage-accounting, faq, limits, errors-and-debugging, streaming, generations, api-keys, tool-calling). Rever antes da Fase 1 e a cada 30 dias: a API muda com frequência.

| Tema | O que a documentação diz | Consequência no CardFactory |
|---|---|---|
| Superfície | Responses API (`/api/v1/responses`) é a superfície destacada; Chat Completions (`/api/v1/chat/completions`) segue documentada e suportada | ADR-0007: usar Chat Completions; adaptador isolado permite migrar |
| Autenticação | `Authorization: Bearer`; cabeçalhos opcionais `HTTP-Referer`, `X-OpenRouter-Title` | Sem dados pessoais nos cabeçalhos; título genérico "CardFactory" |
| Catálogo | `GET /api/v1/models`: `id`, `name`, `context_length`, `pricing` (`prompt`, `completion` obrigatórios; `request`, `image`, `web_search`, `internal_reasoning`, `input_cache_read`, `input_cache_write`…, em USD por token como string), `top_provider.max_completion_tokens`, `supported_parameters` (inclui `structured_outputs`, `response_format`, `tools`, `reasoning`), `architecture.input_modalities`, `reasoning{supported_efforts…}`; endpoints por modelo em `/models/{author}/{slug}/endpoints` | Sincronizar e guardar snapshot com data; preço convertido com Decimal; sem IDs hardcoded |
| Saída estruturada | `response_format: {type: json_schema, json_schema: {name, strict, schema}}`; exigir suporte com `provider.require_parameters=true`; aplicação do `strict` varia por provedor (alguns tratam como dica) | Validação local obrigatória (ADR-0008) |
| Raciocínio | `reasoning: {effort | max_tokens, exclude, enabled}`; tokens de raciocínio são cobrados como saída e contam no `max_tokens`; se esgotarem o orçamento, `finish_reason: "length"` com conteúdo vazio, cobrado | Estimativa de custo inclui raciocínio no teto; tratar como truncamento; não repetir sem aumentar teto |
| Pesquisa web | Ferramenta de servidor `openrouter:web_search` (beta), motores `auto/native/exa/firecrawl/parallel/perplexity`, `max_results` (padrão 5), `allowed_domains`/`excluded_domains`; citações `url_citation{url,title,content,start_index,end_index}`; preço extra por requisição (ex.: Exa US$0,007 até 10 resultados). Plugin `web` e sufixo `:online` estão obsoletos | Pesquisa via server tool com orçamento por pesquisa; URLs citadas são só **candidatas** — o BIB recupera o documento antes de confirmar (BIB-008) |
| PDFs | Conteúdo `file`; plugin `file-parser` com motores `cloudflare-ai` (grátis), `mistral-ocr` (US$2 por 1.000 páginas), `native` (cobrado como tokens) | Extração local primeiro (pypdf/pdfplumber); OCR pago só com orçamento e quando a extração local falhar |
| Roteamento | `provider{order, allow_fallbacks (padrão true), require_parameters, data_collection, zdr, only, ignore, quantizations, sort, max_price}`; campo `models` para fallback entre modelos | Etapas científicas críticas: `allow_fallbacks` controlado, `models` vazio, `max_price` definido; comparar `model` da resposta com o solicitado |
| Uso e custo | `usage` sempre retornado: `prompt_tokens`, `completion_tokens`, `cost` (créditos em USD), `prompt_tokens_details.cached_tokens`, `completion_tokens_details.reasoning_tokens`, `cost_details`; `GET /api/v1/generation?id=` com `total_cost`, `provider_name`, `model`, `finish_reason`, `latency`, `cancelled`, `provider_responses[]` | Custo real por chamada vem daqui; reconciliação por `generation_id` |
| Chave | `GET /api/v1/key`: `limit`, `limit_remaining`, `limit_reset`, `usage`, `usage_daily`…; budgets bloqueiam com 403 antes da chamada | Ler antes de cada execução; recomendar ao proprietário criar chave dedicada com limite (FIN-010) |
| Erros | Corpo `{error:{code,message,metadata}}`; 400, 401, 402 (sem créditos), 403 (permissão/budget/moderação), 408, 429, 502, 503; `metadata.error_type` tipado; erros no meio do stream chegam com `finish_reason: "error"`; não-stream com erro após cabeçalho → 200 só com `error` | Classificação transient/rate_limited/permanent/billing; respeitar `Retry-After` em 429/503 |
| Rate limits | Modelos `:free` têm 20 req/min; limites de modelos pagos **não documentados** por conta | Concorrência conservadora (padrão 2–4) e backoff; nunca modelos `:free` em produção (podem ter outras políticas de dados) |
| Batch | Existe: `POST /api/v1/batches`, status `validating…completed/failed/expired/cancelled`, resultados por `custom_id`, ~50% do preço, expira em 30 dias; **não suporta** pesquisa web, `provider.order`/`sort`, ZDR, cancelamento (só exclusão em estado terminal) | Fora do MVP; candidato para auditoria pedagógica/classificação após benchmark (AMB-16) |
| Cache | Automático em OpenAI, DeepSeek, Gemini 2.5+, Z.ai etc.; `cache_control` explícito em Anthropic/Qwen; preços de leitura/escrita variam | Políticas compartilhadas no início do prompt para favorecer cache; custo de cache lido do `usage` |
| Idempotência | **Não documentada** chave de idempotência | ADR-0009: idempotência local; chamada com resultado incerto não é repetida automaticamente |
| Cancelamento | Abortar stream interrompe cobrança apenas em alguns provedores; requisições não-stream e provedores sem suporte são cobrados integralmente | Cancelamento é cooperativo; custo de chamada cancelada é reconciliado, não presumido zero |

Pontos não confirmados na documentação lida: formato exato do conteúdo `file` no Chat Completions, semântica detalhada do campo `models` de fallback, esquema completo de `/models/{author}/{slug}/endpoints` e de `/api/v1/credits`. Confirmar na Fase 1 com o OpenAPI oficial antes de implementar.
